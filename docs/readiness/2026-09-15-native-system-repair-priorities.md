## Distinct optimization surfaces

Keep three different measurements: activation-guidance target coverage, Perception candidate target inclusion, and final task correctness. Do not report top-eight guidance coverage as Top-N candidate coverage. Retain ordered action occurrences for multi-action speech; candidate union coverage is insufficient to certify complete-action coverage.

Keep the two stores. Activation values should distinguish plausible neighboring actions using scope, device/domain, speech cues, activation conditions and counterconditions. Parameter values should explain meaning, explicit-versus-default-versus-unspecified status, units/ranges, negation/correction and evidence needed for a field. Schema validity alone does not establish that a value was spoken or entailed.

A wrong or incomplete recalled card must not become an implicit closed answer inventory. Candidate formation needs access to a concise complete legal overview; selected detailed values augment it. Downstream Solver needs an explicit route to reconsider a mismatch with speech or the complete registry. Determine the required route from the pending candidate evidence, not from a preference for larger context.

Any acoustic evidence acquisition belongs to the live agent trajectory. Reviewer identifies a concrete suspected problem and its relevant span; Planner chooses acquisition or revision; the local speech tool returns bounded evidence; Solver remains the only answering authority. Whisper is a candidate independent acoustic decoder, not an unconditional preprocessing stage. Reuse shared native tool/execution paths; do not add a dataset-specific control framework.

Runtime triggers must use observable evidence, such as incompatible action alternatives, missing speech support for an argument, unclear names/numbers, or disagreement between source-grounded constraints and the current answer. An offline gold miss, a true error label or final scoring feedback is never a runtime trigger. Candidate width is not calibrated confidence.

## Separation from algorithmic training-free RL

The current root-led diagnosis and engineering establish a controllable system. They are not an RL algorithm. After a usable system is fixed, its available action workspace can include which knowledge view to acquire, which evidence tool/span to use, whether to reconsider candidates, whether to revise, and when to stop. Define source-bound states, observable actions, complete sampled trajectories and outcomes before choosing sampling or policy-update rules.

Later algorithm work must specify proposal/sampling distributions, group-relative trajectory evaluation, update targets outside frozen model weights, held-out validation and stopping rules. It must optimize actual trajectories or reusable external policy state, not rename hand-authored GPT decisions as training-free RL. Do not expand this algorithm stage ahead of the system evidence.
