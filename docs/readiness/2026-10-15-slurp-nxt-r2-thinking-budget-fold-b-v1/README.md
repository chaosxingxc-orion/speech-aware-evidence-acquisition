## Read rule (preregistered)

`scripts/analysis/slurp_nxt_thinking_budget_column_read.py`: every arm's first Solver answer is scored once, complete, by the official scorer; each candidate arm minus the delivering `budget-3072` arm, SLU-F1 and intent, paired per row, utterance-cluster bootstrap (10,000 draws, seed 20261015). NO twin flies, so the null is the DECLARED same-core A/A offset |o| = 1.15 pp SLU (the larger of the two measured offsets: 268-B +1.15 / intent -0.09; P3.1 -0.61 / intent +1.6) and the paired floor is 0.7 pp (decisions 172/231/313). Words (fixed here, in the reader; the first that applies):

* **GAIN**: SLU CI95 lower bound above +|o| (the cheaper budget RAISES the score beyond the declared A/A width).
* **NEEDS-FULL-BUDGET**: SLU CI95 upper bound below -|o| (the cheaper budget loses more than the declared A/A width).
* **CHEAPER-AT-NO-RESOLVED-LOSS**: SLU CI95 lower bound >= -1.49 pp and intent CI95 lower bound >= -0.65 pp (decision 190 floors): any loss is inside the design's own resolution, so the cheaper budget may replace the locked one.
* **UNRESOLVED**: none of the above (the interval is too wide to call the budget cheaper at no loss, and the loss is not beyond |o|).

The read also reports, per arm and node: completion tokens (mean / p50 / p90 / p99 / max), the finish-reason table, cap hits, empty completions, FORCED CLOSES (contacts that hit the budget), reasoning-character and think-marker counts, seconds per contact, and the THROUGHPUT table (seconds per row, rows per minute at 4 slots, GPU-h per 1,080-row lock flight at each budget, each arm's measured cost in delivering rows beside the registered cost). claims_benefit is false; development numbers only (owner decisions 28 and 86).
