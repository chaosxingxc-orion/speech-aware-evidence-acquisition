## Task-native role design

The E21 target remains verbatim transcription with separate PERSON, overall WER, non-entity,
numeric and insertion analysis. The current-window hypothesis is an uncertain word or entity,
not an SLURP intent label. Preserve the source window and whole-call evaluation population.

- Perception identifies current-window linguistic structure and uncertain names or numbers.
  Its state is task evidence; it does not deliver the final transcript.
- Solver drafts the full transcript from the audio and legal supplied context, then retains
  final answer authority if a bounded revision is requested.
- Reviewer identifies a concrete possible defect and its acoustic or semantic evidence gap.
  A high-confidence problem can justify an analytical tool request; confidence that an answer
  is correct is not a trigger.
- Planner accepts or requests a bounded Solver revision using those evidence and review records.
  Existing Reviewer/Planner ReAct tool calls implement on-demand acquisition. Do not claim that
  the optional graph ACQUIRE node is configurable when the public schema exposes only the
  working ACCEPT/REVISE route.

Build separately named ConEC views through the shared KnowledgeSnapshot and store interfaces.
The existing external-governed source role can represent public roster/document knowledge;
do not invent TRAIN samples or derive context from reference transcripts.

The discriminative view should preserve plausible written forms, roles, organizations and
source-grounded cues that separate confusable names. The explanatory view should preserve
canonical forms, entity roles and lawful normalization/repair constraints. A published roster
does not establish that a name was spoken. Numeric facts in a press release must not overwrite
different numbers supported by the audio. Runtime consumption must remain bound to the current
call's public source documents, with protected annotations excluded.

First freeze this window-local system. Any later dialogue or speaker-conditioned summary
mechanism remains a separate task-metric hypothesis; it is not needed to close this execution
bridge and does not establish a meeting-minutes evaluator.
