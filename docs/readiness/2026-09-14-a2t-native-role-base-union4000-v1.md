# Audio2Tool native role base: complete configuration preparation

Status: configuration preparation; generation is not admitted. This prospective
comparison transfers the shared native agent base to the already exposed
4000-row Audio2Tool union. It does not reopen the closed fixed-stage study.

## Method and comparison

Both arms use the complete original speech packet, the existing official
task contract and compact full 152-tool registry, the same frozen core,
greedy decoding, output ceiling 2048, controller, FlightRuntime and
OpenJiuwen executor. Direct uses phase-direct-only-v1 with no supplied
knowledge or analytical tools. Its hidden parameter snapshot supports the shared\nleakage guard without routing any knowledge to the model; its single direct\nphase retains the whole-roster barrier required by live_phase_fit. The native system uses
phase-audio2tool-native-candidates-review-revise-v1.

The native graph runs Perception, Solver, Reviewer, then Planner, with one
possible Solver revision. Perception receives up to eight speech-retrieved
tool-activation values. It emits up to eight ordered action occurrences,
with up to four alternative tool names per occurrence. Repeated actions
remain separate occurrences; repeated alternatives are discouraged in the
prompt and preserved by the parser if produced, never silently padded.

Solver receives the one released parameter explanation for each distinct
candidate tool, up to 32 values. It can choose outside the Perception
candidates from the complete legal registry. It may resolve missing actions
from the original speech; eight is an intermediate hypothesis capacity,
not a final task action-count limit or a known dataset maximum.

Reviewer can choose to check the task contract when a concrete apparent
violation or ambiguity warrants it. A lookup is not forced. The tool supplies
authoritative contract evidence, not an independent answer. This first
transfer does not yet establish selective ASR or new acoustic information.
Planner chooses ACCEPT or REVISE. There is no separate acquisition node in
this configuration; its prompt explicitly forbids ACQUIRE. The config retains
the framework's required three-token action vocabulary without inventing a
tool or an acquisition edge.

## Bounds and delivery

Eight action hypotheses and four alternatives are prospective operational
choices, independently of activation retrieval K=8. They exceed the synthetic
five-occurrence proof and allow ambiguity within each occurrence. They are
not inferred from gold action counts, old SELECT/FILL caps or SLURP Top-3.

The common 2048-token output ceiling gives the structured multi-action state
more room than the old 1024-token task answer ceiling. Both direct and system
are regenerated under the new common ceiling; old outputs remain historical.
Perception evidence is prompted to twelve English words per occurrence.
Strings and lists are not separately grammar-capped, so 2048 bounds the whole
role output and finite completion is reported explicitly.

Role iteration limits are Perception 1, Solver 1, Reviewer 3 and Planner 1,
with one revision: 1 + 2*(1+3+1) = 11 maximum model contacts per sample.
Reviewer reserves its final iteration for findings. Exhaustion preserves the
latest Solver answer; source-bound output-length/content-filter terminations
deliver the latest complete Solver or an abstention. Partial tool calls are
never executed. Malformed source states or unsupported termination remain
failures, not successful abstentions.

The proposed model geometry is 98,304 total context in three 32,768-token
slots. A separately declared two-slot model offers 49,152 tokens per slot.
The comparison's geometry must be settled as a whole before generation;
the fallback is not permission to switch mid-run. Real capacity remains
unverified. The runtime must fit every actual role request before dispatch.
