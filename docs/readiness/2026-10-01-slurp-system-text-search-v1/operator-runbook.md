# System-text search operator runbook

Use the existing shared flight lifecycle. These commands do not launch models,
score, clear STOP, retry, grant result access or release held work. Run them from
the serially integrated, frozen source version in Ubuntu-24.04 with the pinned
speechrl environment. Keep large policies, responses and trajectories under the
data root; never commit them to Git.

## Initial feedback and each update

Import the prepared seed with `import-seed --bundle <data-root seed-policy.json>`
and an archive outside Git. The bundle identity in `protocol.json` is the seed
identity, not a scientific winner.

Register the complete family and exact member-to-run bindings before generation.
A family specification has exactly `family_id`, `expected_members`, `bindings`,
`initial_reference_member` and `reference_family`. Initial feedback references
the initial seed; later feedback points to that original family rather than
re-estimating F_ref. Use the shared reward-source binding schema for each member.
The reader revalidates every attempt, seal and unique complete official score
before opening outcomes. Countersign the family-specific READ record first.

Use `feedback --family <spec> --output <new-feedback-file>` only after that read
gate. It retains every registered row, terminal disposition, official counts,
costs and trace pins. Cached feedback JSON alone is not read authority.

Use `proposal-input` with branch, round, slot, seed/parent identities, pinned
protocol, model version and a fresh session identity. L additionally supplies
the complete preceding family and its explicit learning-member list. Its view
is projected after whole-family qualification and relative returns are
recomputed without B. Earlier L inputs, failed responses and dispositions have
hash-bound indexes. B rejects feedback/complementary arguments before opening
them, and its parent must always be the original seed.

Invoke the isolated proposer once for that allocation. The external transport
must expose only the packet and exact allowed indexed files. Import its receipt
with `import-response`. Required receipt fields are `raw_response`, `session_id`,
`model_version`, `input_sha256`, `input_tokens` and `output_tokens`; preserve null
for genuinely unavailable token counts. Invalid, over-budget, wrong-session,
duplicate and no-change responses remain recorded and consume their allocation.
Never call again to obtain a more convenient proposal.

Use `compile-candidate` with the same protocol, seed configuration, parent
archive, exact next-round evaluation roster, data root and isolated staging
directory. It refuses cumulative source overlap and undeclared edits. A change
to construction instructions or values requires a separately registered actual
construction generation and a verified release link. The construction reader
joins each output to its own request instruction and sample, applies the existing
semantic edit contract and verifies the prepared release. No construction call
may borrow a task-generation allocation.

Prepare and register each candidate's own supply, FIT, generation and scoring
identity through the existing flight machinery. Freeze the admitted family,
including any pre-contact invalid-proposal exclusions. Failure after admission
never permits a partial-family update. Dynamic round registrations and their
coordinator admissions have not yet been materialized.

## Selection and scientific read

Keep all candidates and failures. `SystemSearchArchive.retain` requires one
common cohort, true non-dominance, and at most two active versions per branch;
its result is explicitly search-only. Apply the preregistered tie-break and
intent protection from `analysis-recipe-v1.json`. Do not mix point estimates
from different rounds. The blind proposer must not see evaluator selections.

Reevaluate survivors on the common selection cohort. Freeze the chosen L/B
versions before DEV, then run seed/A/A and both finalists on the registered
1,000 rows. Root reads the entire completed family and reports L-B primarily,
L-seed secondarily, uncertainty, strata, reliability and actual costs. No
automatic extra samples, adoption, new allowance or recursive-improvement claim
follows from point estimates.
