## Existing implementation and required extension

The shared NativeEpisodeWorkflow already implements Perception -> Solver -> explicit
accept when review_loop_enabled is false. Reviewer and Planner are not instantiated.
The configuration requires reviewer iterations0, planner iterations0 and revisions0;
an optional review_loop=off marker must agree. This is an execution configuration change,
not a field currently writable by the text-policy proposer.

Current native role tool validation explicitly limits analytical tools to Reviewer and
Planner. The present seed assigns its single bounded lookup to Planner. Simply deleting
review therefore removes active knowledge access too. A Solver-first lookup needs a
prospective shared-runtime extension with explicit authority, tool-result custody,
iteration/output reserves and contact accounting. Reuse the same TaskAdapter,
KnowledgeProvider, EvidenceAgentController, FlightRuntime and OpenJiuwen executor.
Do not create a second answerer, replace the scorer or manufacture a tool call in text.

Keep the existing lookup API, frozen store and result limits: at most one active lookup
and at most two slot identifiers. Enforce limits in code rather than relying on lengthy
reminders. Preserve empty/failure results and prevent invalid or unbound calls before
transport. Solver retains final Omni answer authority. This is a prospective design;
the extension is not yet implemented or admitted.

## Measurement and acceptance

Keep official SLU-F1, intent and reliable completion primary. Report raw/final parse
validity, entity/full-answer transitions with normalization effects separate, actual
lookup requests/execution/result visibility, protected tool bounds and failure states.
For intentionally absent Reviewer nodes mark review metrics not-applicable-by-design;
do not encode them as zero detection or missing instrumentation. Track first/non-first
sample latency, prompt/decode/queue time, tokens and calls as secondary costs.

Retain the complete family, exact seals/unique official scores and root READ before
interpreting outcomes. Preserve scenario strata, denominators, missingness, uncertainty
and own A/A. N20 is reused optimization/form evidence, not independent validation.
Root reviews progression within owner227 bounds and returns before8x400 or an equivalent
split. No quality/learning gain or deployment adoption is established by this design.
